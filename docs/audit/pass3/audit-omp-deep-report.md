### 1.1 Bottom line

**The mechanism half of the claim is largely CONFIRMED; the number half is NOT-VERIFIABLE from the repo.** oh-my-pi is engineered like a latency-first harness — parallel tool batches by default, a byte-stable prefix with an explicit cache-preservation contract, output-budget clamping, a shell minimiser on by default, a difficulty-routed thinking knob, and a four-adapter benchmark manager with a microVM Terminal-Bench runner. But: no committed result files, no median agent-runtime metric (the manager reports a mean), and no 72% figure. The comparable in-repo claims (68.3% edit success, -61% output tokens, 2.1x pass rate) are single-line marketing rows with **no stated metric/anchor/population/excludes** — exactly the contract the sibling repo Reasonix formalises and this one does not.

### 2.2 Prompt/token engineering tooling (`scripts/`) — deeper than the prior pass

- **`scripts/rewrite-system-prompt.ts` + `.style.md`** — confirmed and now fully characterised. The style guide is a *voice contract*: drop articles and subjects, open clauses with a fixed verb set (`Need`, `Could`, `We'll`, `Let's`), hedge with bare particles, end deliberations with one-word verdicts ("Fine."), chain micro-clauses with semicolons, present tense. Hard constraints: preserve every technical token exactly (backtick spans, tags, `{{…}}`, URLs, paths, flags, numbers) *with the same number of occurrences*; keep RFC-2119 keywords uppercase; one-fragment-in-one-fragment-out. The script runs line-by-line, peels list/indent prefixes and wrapping `{{#…}}` tokens off prose lines, batches as id-keyed JSON to Sonnet 4.5 via OpenRouter (default `anthropic/claude-sonnet-4.5`, `--chunk 3`, `--concurrency 6`, `--temperature 0.4`), and **falls back to the original line whenever a rewrite drops a token** (`scripts/rewrite-system-prompt.ts#L5-L40`).
- **`scripts/tool-prompt-usage.ts`** — per-template token accounting with `--json` and `--encoding cl100k_base`; the measurement half of the same pipeline.
- **`scripts/session-stats/`** — a 17-file research kit over the local session corpus: `sync.py` (SQLite into `~/.omp/stats.db`), `analyze.py` (`tools|edits|followups` subcommands), `audit.ts` + `audit-prompt.md` (LLM-assisted token-usage audit), `read_optimizer.py`, `optimize_read_config.py`, `analyze_selector_reads.py`, `plot_read_summarizer.py`, `analyze_search_relevance.py`, `harmony_backtest.py`, `plot_tools.py` (`scripts/session-stats/README.md#L1-L16`). This is the repo analysing *its own agent transcripts* to tune the read summarizer and search. Prior reports named the directory; none named a single script.
- **`scripts/cleanup-scan.ts`** — a ranked-candidate scanner for the `/cleanup` command: clone detection (normalised line-window hashing), god-objects (LOC/exports/class methods), junk-drawers (`utils|helpers|misc|common`), dead-exports tiered by exports-map exposure, deep-imports (`../../..`), check-density hotspots (`as`-casts, `?.`, `??`) (`scripts/cleanup-scan.ts#L1-L16`).

### 2.3 `packages/catalog` — the KDL cascade is a *rule engine*, not a config format

- **`src/compat/cascade.ts` (429 lines) is a ranked multi-axis resolver and a self-declared port**: *"Faithful port of the o2 reference resolver (`cascade.rs`): rules are conjunctions over `(class, provider, api, upstream, family, revision, models)`; per axis the matching rule with the greatest `(model-selector exactness, constrained-dimension count, priority)` tuple wins, and an equal-tuple same-axis contest throws `AmbiguousOverlapError`. Declaration and file order are never semantic."* (`cascade.ts#L1-L11`). Three axes resolve independently: `wire`, `thinking`, `catalog` (`#L415-L428`). Selectors are `exact | glob | token` (`#L203-L212`); revisions are parsed and satisfied by `revisionSatisfies` (`#L225-L227`). Results are memoised in a 16384-entry LRU and **cloned** on return because "nested rule values are applied to mutable compat records; the cached canonical graph must never escape" (`#L296`, `#L343-L354`). `AmbiguousOverlapError` is documented as CI-time for bundled targets: *"fix with an explicit `priority=` in the KDL, never in code"* (`#L18-L22`).
- **`auth/` rules (103 files) declare OAuth login flows as data.** `rules/auth/anthropic.kdl` carries `org-scoped-identity`, `login "oauth-code"` with a base64-stored `client-id`, `authorize-url`, six `scopes`, `pkce #true`, `authorize-params { code "true" }`, a `callback port=54545 path="/callback"`, the `token url=… body="json"` exchange, a `credential` mapping (`access`/`refresh`/`expires` with `skew-ms`, `account-id "account.uuid"`, `email`, `org-id`, `org-name`), and an `after-exchange hook="anthropic-identity"` fallback. ## 4. STEAL LIST

Ordered by *value per unit of adoption cost*, not by size. Each item is something an agent harness can adopt without adopting oh-my-pi's whole architecture. 28 items.

1. **Declare tool concurrency per tool, default to shared, and run the batch in parallel.** `agent-loop.ts#L3906-L3940` builds `sharedTasks` with a `lastExclusive` barrier and awaits `Promise.allSettled`. Default `"shared"`, overridden per tool (`types.ts#L1198`); only `edit`/`write`/`ask`/`debug`/`todo`/`eval` opt out, and `bash` is conditional on `pty` (`bash.ts#L674-L678`). *Why:* every turn's independent reads and searches overlap instead of serialising, which is the single largest wall-clock win available to a tool-calling loop, and it costs one optional field on the tool interface.

2. **Make the system prompt + tool specs a frozen, fingerprinted prefix and keep the message log append-only.** `append-only-context.ts#L99-L166` + `#L343-L391`. The fast-path key is prompt *segments* plus a per-tool wire-identity string, and `syncMessages` truncates the log to the **longest byte-stable prefix** on any in-place rewrite. *Why:* it converts "prompt caching" from a hope into a contract, and the comment records the regression it prevents (a full ~40k-token re-prefill per turn on local backends, issue #3406).

3. **Gate that cache mode per provider from data, and default to auto.** `rules/runtime/behavior.kdl` `append-only-context-providers`; `provider.appendOnlyContext` default `auto` (`session/settings.ts#L1530-L1545`). *Why:* correctness — a provider that rewrites history between turns would be *hurt* by append-only semantics, so the switch belongs in the provider rulebook, not in user settings.

4. **Fit the output cap to the remaining context window on every request.** `output-budget.ts#L81-L96`, with a proportional margin (`PROMPT_ESTIMATE_MARGIN_DIVISOR = 10`), a per-message framing charge (`MESSAGE_FRAMING_TOKENS = 16`) and an absolute headway (`OUTPUT_FIT_HEADWAY_TOKENS = 64`, empirically measured against a 262k-token host that returned 400s at +11 to +42 tokens over). *Why:* it removes an entire class of hard 400 failures on large-output models without touching compaction thresholds, and the constants are the measured values, not guesses.

5. **Anchor prompt-size estimation on the provider's own reported usage.** `output-budget.ts#L133-L144` uses `findRequestUsageAnchor` to take the newest trustworthy assistant turn's reported tokens and locally count only the messages appended after it, falling back to a full local count only when nothing anchors. *Why:* local tokenizers are wrong by a few percent; anchoring makes the estimate exact for the expensive part and local for the cheap tail.

6. **Charge framing tokens per message.** `MESSAGE_FRAMING_TOKENS = 16`, because "many short messages (a turn's parallel tool results) leave this uncovered" by a proportional margin (`output-budget.ts#L20-L29`). *Why:* parallel tool batches are exactly the case that breaks proportional margins, and every harness that adopts item 1 will hit it.

7. **Cap tool output by lines *and* bytes with a spill-to-artifact default, and enable a shell minimiser by default.** `DEFAULT_MAX_LINES = 3000` / `DEFAULT_MAX_BYTES = 50 * 1024` / 16 MiB artifact (`packages/tui/src/tools/streaming-output.ts#L13-L19`); `shellMinimizer.enabled` default **true**, "Compress verbose shell output (git, npm, cargo, etc.) before returning it to the agent" (`exec/settings.ts#L211-L219`). *Why:* output volume is the dominant token cost in a coding agent, and 3000 lines is generous enough that the cap is invisible until it saves a fortune.

8. **Summarise reads structurally instead of dumping file content.** `tools/read-summary.ts#L42-L43` (`MAX_SUMMARY_BYTES = 2 MiB`, `MAX_SUMMARY_LINES = 20 000`) plus the profile-summariser path in `tools/read.ts#L2348-L2361`; the repo also has the tuning scripts (`session-stats/read_optimizer.py`, `optimize_read_config.py`). *Why:* a read that returns a summary plus addresses keeps the file addressable without paying for it, and the tuning scripts show the selector and config can be *measured* rather than argued about.

9. **Intercept shell commands that have a dedicated tool.** `exec/settings.ts#L19-L100`: **10 ordered rules** — 7 redirect `cat/head/tail`, `grep`, `find/fd`, `sed -i`, `perl -i`, `awk -i inplace` and stdout redirection to the dedicated tool with a user-facing message (each with a comment explaining exactly which forms are and are not matched — the `echo`/`cat` redirect rule alone is a 100+ character regex reasoned through fd-duplication, quoting and command substitution), and 3 keep `bash` but force its managed `name` form so a service/watcher/debugger stays observable instead of leaking into `nohup ... &`. *Why:* it prevents the most common token-wasting failure mode (dumping a file through the shell) and makes long-running processes managed by construction. Note it defaults `false` — adopt it *on*.

10. **Auto-background long commands and keep working.** `exec/settings.ts#L131-L137` (`bash.autoBackground.enabled` default **true**), `thresholdMs` default 60 000 (`#L286-L290`), with the wait racing a steering signal so a queued user message backgrounds the job early (`tools/bash.ts#L1420-L1453`). *Why:* it removes the dead round trip on builds and tests without changing the model's behaviour or the tool's semantics.

11. **Re-execute an unpaired tool-call tail instead of starting a new model turn.** `agent-loop.ts#L1302-L1346`: a trailing assistant message with unpaired tool calls is run *before* the first model call, with the explicit reason that injecting steering between `tool_use` and its results would break the provider pairing invariant. *Why:* retries and resumes stop paying for a model call they do not need.

12. **Let the user's queued message land inside the in-flight response.** `openLiveSteering` (`agent-loop.ts#L1947-L1986`) offers queued steering to a provider that can deliver it mid-stream, with a deliberate refusal path for image-bearing messages ("provider-context transforms rewrite images"). *Why:* it removes a full round trip from the most latency-visible interaction there is.

13. **Keep loop guards as prompt files, one per failure class.** `prompts/system/thinking-loop-redirect.md` and `tool-call-loop-redirect.md` are terse corrective notices emitted inside a `<system-interrupt reason="...">` wrapper, telling the model to stop re-planning or to never repeat identical arguments. *Why:* it is the cheapest intervention that actually breaks a loop, and the file-per-class structure makes each one reviewable and testable.

14. **Route thinking effort by a cheap difficulty judgment, and cap the automatic ceiling one tier below max.** `auto-thinking/classifier.ts#L135-L138` ("The default keeps `auto` one tier below the top, so only an explicit `ultrathink` reaches `Effort.Max`"), with `thinkingBudgets.*` per-level token budgets (`session/settings.ts#L1547-L1553`). *Why:* it makes "don't overthink the trivial prompt" a policy instead of a hope, and the ceiling rule keeps the top tier meaningful.

15. **Make the perf/quality handoff a judged, one-shot, gated switch with a fail-open policy.** `docs/prewalk.md#L117-L125` — three routes (`prewalk`/`primary`/`direct`), "a wrong handoff costs more than a missed one", a fixed 0.70 gate, and fail-open behaviour documented per failure (`#L158-L160`). *Why:* it is the only honest "trade reasoning for velocity" design in the repo, and its decision contract is copyable even if the models are not.

16. **Express provider wire/auth/quota compat as compiled data with a ranked resolver that errors on ambiguity.** `compat/cascade.ts#L1-L11`, `#L248-L270`; 245 `.kdl` -> `rules.json`. *Why:* it makes "we support 60+ providers" auditable, a new provider a data change, and a tie a CI failure instead of a silent precedence accident.

17. **Ship the edit engine with cross-implementation parity fixtures and byte-identical error strings.** `crates/pi-edit/src/lib.rs#L16-L19`, `tests/fixtures/*/parity_*.json`. *Why:* models are trained on specific error text; if you port the engine, the fixtures are what stop the port from quietly degrading landing rates.

18. **Build the shell test host as a deterministic, event-recording, leak-checking simulator.** `crates/pi-shell/src/testkit/host.rs#L1-L16` (1 µs clock per read, jump to next deadline when all vprocs wait, JSON event log, `assert_no_leaks` per case). *Why:* it turns "did we break the shell" into a differential corpus you can run in CI, and the fake-clock design makes cancellation and timeout tests deterministic.

19. **Keep a failure minimizer next to the test corpus.** `crates/pi-shell/src/minimizer/**` with `tests/fixtures/minimizer/{cargo,git,glab,go,jvm,npm}`. *Why:* shrinking a failing shell script to the two lines that matter is the difference between a report and a fix, and the corpus is what proves the reducer works.

20. **Rule-matched rules: attach a regex `condition` and a tool scope to each language rule.** `discovery/builtin-rules/ts-no-any.md#L1-L6` (`condition`, `scope: "tool:edit(*.ts)"`, `interruptMode: never`); rules ship inside the binary via `with { type: "text" }` and are the *lowest* priority so anything user/project-level overrides them. *Why:* rules that fire only when the edit actually contains the anti-pattern cost nothing on every other edit, and shipping them embedded keeps a compiled binary self-contained.

21. **Obfuscate secrets reversibly with a per-install key and keep the placeholder stable across sessions.** `secrets/index.ts#L13-L22`, `secrets/placeholder.ts#L8-L15`. *Why:* redacting secrets out of provider traffic is table stakes; making the redaction reversible and cross-session stable is what stops it from corrupting persisted transcripts, and the per-install key is what stops the placeholder from being dictionary-reversed.

22. **Fast-path a whole-context secret scan with required literal substrings.** `secrets/patterns.ts#L8-L18` (`literalPrefixes` — skip the regex when the text contains none of them). *Why:* this scan runs on every request over the whole provider context; `includes` beats a lookbehind by orders of magnitude and the constraint is mechanically checkable.

23. **Put the parts the model must not be able to argue with in the host.** `ratchet/ratchet.ts#L1-L10` — approval freshness by content hash, frozen split, completeness and held-out-leakage checks, round decision. *Why:* an eval hillclimb whose keep/revert logic lives in a prompt is not a gate; this is the smallest correct boundary, and the on-disk layout matches a known eval report format so the tooling interoperates.

24. **Compute benchmark ground truth locally, encode stimuli so paraphrase cannot help, and derive every trial from an index.** `if-bench/actions.ts#L1-L11` ("the expected result is computed locally by `applyActions` rather than trusted from the model"; glyph-only actions "so the model cannot lean on natural-language paraphrase"; "generated from (their) absolute index, so a run is fully reproducible"). *Why:* it is a benchmark design that survives model improvement without becoming a different benchmark.

25. **Make every discoverable-config source a provider behind one capability registry.** `capability/types.ts#L1-L20` — `load("mcps")` instead of every caller knowing `.claude`/`.codex`/`.gemini`, with `explicit` vs `configured` roots and `merge` vs `explicit-only` modes. *Why:* it turns "support another tool's config layout" into adding a provider, and it is how the harness reads foreign agents' config directories without special cases.

26. **Give the codebase a prompt-rewriting pipeline whose invariant is mechanical.** `scripts/rewrite-system-prompt.ts#L5-L40` + `.style.md#L1-L40`: keep every fragile token byte-exact *with the same occurrence count*, fall back to the original line on any drop. *Why:* prompt prose is the densest surviving form of token waste, and this is the only prompt-compression scheme seen across the four audits that cannot silently delete a contract.

27. **Own the benchmark manager, not just the benchmark.** `packages/metaharness/src/benchmarks.ts#L23-L46` adapters with `MetricDefinition` (`key`, `label`, `format`, `higherIsBetter`), arms grouped by job-name prefix with linear projections for in-flight arms (`experiments.ts#L11-L22`), and a resume path that recovers the original launch flags from a snapshotted `runner-config.json`. *Why:* comparing arms is where benchmarks stop being theatre, and "resume without re-specifying" is what makes a long run survivable.

28. **Analyse your own session corpus to tune your own tools.** `scripts/session-stats/**` (17 files). *Why:* the read summariser, the search relevance and the selector behaviour in this repo have Python scripts that read the users' own transcripts; that feedback loop is what separates tuning from taste.

## 5. Optimisation + what-to-do candidates

### 5.1 Correctness / drift

1. **`docs/tools/` documents 34 tools while `BUILTIN_TOOL_NAMES` lists 30 + 3 hidden, and 88 files live in `prompts/tools/`.** The docs cover `browser`, `computer`, `generate_image`, `tts` (which are eval preludes, not registry tools) and omit `ast_edit`, `context_notes`, `new_context`, and the notice templates. A generated index — one row per tool, marked *registry / prelude / template* — would have caught this and would also satisfy the "prompt corpus has no index" gap both prior reports flagged.
2. **The 279-file prompt corpus still has no index, and the highest-value part of it is unlabelled.** 42 of the 88 `tools/` files are *result and notice templates*, not descriptions (`isolation-error.md`, `cfg-env-shadowed.md`, `write-device-only-refusal.md`, ...). An index that classifies each file as `description | result-template | notice | protocol | judgement-contract` makes the tree navigable to a maintainer, not just to a searcher.
3. **`bashInterceptor.enabled` defaults `false` while its rules already ship.** The interceptor is the cheapest token win in the tree (steal item 9) and it is off. Either enable it by default behind a one-line notice on first interception, or state in `docs/bash-tool-runtime.md` why it is not on.
4. **The KDL cascade has a reference doc but no authoring doc.** `provider-compat-reference.md` explains resolution; nothing explains how to add a provider, regenerate the census, or add a `priority=` when `AmbiguousOverlapError` fires — even though the error message itself instructs the maintainer to do exactly that (`cascade.ts#L18-L22`). A one-page "adding a rule" doc plus the regeneration command closes the biggest maintainability hole in the compat layer.
5. **`docs/` still does not document `if-bench`, `ratchet`, or the metaharness metric contract.** These are three evaluation mechanisms with real user-facing entry points (`omp if-bench`, `/ratchet`, `bun run serve --port 4700`) and no doc page. `packages/metaharness/README.md` is excellent but lives under `packages/`.

### 5.2 Speed

6. **`agent-session.ts` is 15,853 lines and `sdk.ts` is 5,979.** `agent-session.ts` is larger than the entire agent loop (`agent-loop.ts`, 4,171) plus the compaction subsystem combined, and it is the file every session feature edits. Extracting the contiguous concerns that already have their own settings and tests — memory wiring, prewalk, todo cycle, IRC, cost gate, model selection — into modules would cut incremental rebuild and review cost on the hottest file in the repo. The repo already applies this principle inside `packages/agent` (loop, compaction, tokenizer and speculative execution are separate modules); the application layer has not followed.
7. **`streamAssistantResponse` (about 660 lines, `agent-loop.ts#L2052-L2710`) inlines the whole stream-event switch, both finalisation paths, Harmony/DSML recovery, the speculation lifecycle, Cursor result collection and abort racing.** The two finalisation paths (the `done`/`error` branch at `#L2333-L2421` and the trailing branch at `#L2626-L2700`) are large near-duplicates differing mainly in whether a partial was already added. A shared `finalizeAssistantMessage(message, { addedPartial })` would make the two paths provably agree, which is the invariant the surrounding comments keep asserting.
8. **The prompt-corpus import path is already build-time text, so the remaining risk is per-turn templating.** Precompile the Handlebars and memoise per (template, static-params) key, then assert the compiled cache is hit in a test — the system prompt is rebuilt whenever a tool roster or setting changes (`agent-session.ts#L11817-L11821` invalidates the frozen snapshot on `/new`, model and setting changes).
9. **`if-bench` and `/ratchet` are local-only gates; neither has a CI dry-run.** A `--dry` scripted-provider mode (as the sibling Reasonix benchmark suites have) would let both run in CI without keys and catch harness rot, which today can only be found by running the real thing.

### 5.3 Accuracy

10. **There is no golden-file test for the base system prompt.** `system-prompt.md` is rendered per session from dozens of conditionals, so "what the prompt actually said in this configuration" is only observable at runtime. A handful of golden renderings (minimal toolset, full toolset, subagent, judge-only) would pin the prompt the way Reasonix pins its base prompt with `internal/assembly/boot/testdata/golden/system_prompt.txt`.
11. **No committed token budget for the prompt corpus.** `scripts/tool-prompt-usage.ts` can measure it and the rewrite pipeline can shrink it, but nothing fails a build when it grows. Committing the measured total per group (system prompt, tool descriptions, result templates, rules) and failing on growth makes prompt bloat a reviewable diff — the same move Reasonix already made with `schema_budget.json`.
12. **`scripts/rewrite-system-prompt.ts` has no `--check` mode.** It can rewrite in place or dry-run, but it cannot verify that the committed prompts still satisfy the style contract. A `--check` that runs the structural-token survival validation over the current corpus and exits non-zero would let CI enforce it without network calls.
13. **The benchmark numbers still have no stated population or exclusions.** README's "6.7% -> 68.3%", "+5 pp", "-61% tokens", "2.1x" are the only committed results, and the metaharness stores `meanTrialMs`/`passPct`/`costPerTask` per arm with no metric contract in the artifacts. Adopting the four-line contract (Metric / Anchor / Population / Excludes) in `packages/metaharness/README.md` and in every `report.md` would make cross-version comparisons mean one thing.
14. **The answer-isolation precondition is not asserted in `if-bench` or `/ratchet`.** Both grade agent output against material that may be readable from the same filesystem. Reasonix refuses to run answer-bearing tasks without an OS read sandbox (`cmd/e2ebench/answer_isolation.go`, `sandbox.ConfinesByDefault()`); the same one-line precondition belongs in both runners here, and `if-bench` is the easy case because its ground truth is computed locally from an index.
15. **`if-bench` has no explicit reporting of the two failure modes it was designed to separate.** Its doc claims the design "makes the two failure modes separable from a single reply" (losing the array vs dropping the cat sound) — the reported score should therefore carry the two components, not just the depth, so a model change is attributable to one or the other.

### 5.4 Cost

16. **The `@smol`/`@slow`/`judge`/`tiny` role ladders resolve through `role-defaults` in `behavior.kdl`, but nothing reports which arm of the ladder actually served a session.** `role-defaults` lists dozens of candidate ids per role in preference order (`slow` alone lists about 30), and resolution picks the first authenticated and enabled one. Journaling the resolved role target per session (the prewalk verdict is already journaled as `auto-prewalk` usage, `docs/prewalk.md#L160`) would make "which model am I actually paying for" answerable without a debugger.
17. **`thinkingBudgets.max` and `thinkingBudgets.xhigh` are both 32 768 (`session/settings.ts#L1552-L1553`), while `auto`'s ceiling defaults to `XHigh`.** That makes the documented "one tier below the top" rule moot for any model that caps out at the same number on both tiers — the intent is a *ceiling*, so the two values should differ or the ceiling rule should be stated in terms of `Effort` rather than the budget number.
18. **Speculative execution exists with an approval-parity gate, but the repo commits no measurement of its hit rate.** `speculation/host.ts` and `agent-loop.ts#L2262-L2270`/`#L2388-L2406` implement launch/reconcile/commit/discard and `SpeculativeOperationCoordinator`; there is no counter surfaced for "candidates started" vs "candidates committed", which is the one number that tells you whether the feature is earning its complexity. The metaharness trace pipeline already normalises per-trial data — this belongs there.
19. **The `web/` role ladder lists ten providers in preference order before any fallback, and `image`/`speech`/`dictation` are similarly long.** Each fallback step is a silent capability downgrade a user cannot see. Surfacing the resolved provider for a search or a TTS call in the tool result details (the `bash` tool already returns a `spotlight`/`service` details block) would make the downgrade visible where it happens.
20. **`ovnfs` daemons are advertised to the model as the default way to make a second copy, but nothing in the tool results says whether the search ran in the overlay or fell back to native.** `ovnfs/search.ts#L1-L11` documents a silent fallback on daemon failure (except abort/timeout). Recording that choice in the grep/glob result details would make the performance implication observable and the fallback diagnosable.
