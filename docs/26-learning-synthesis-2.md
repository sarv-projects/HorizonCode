## 2. Repo-by-repo distillation

### 2.1 wshobson/agents — the subagent corpus (202 agents, 92 plugins, content only)

**What it is:** a corpus of Claude-Code agent definitions in Markdown+frontmatter with per-harness adapters (`.codex-plugin`, `.cursor-plugin` manifests generated by `make generate-all`). No runtime; the host supplies everything.

**Census (verified by script over the tree):** 202 agents across 92 plugins; model distribution sonnet 35 % / opus 27 % / inherit 26 % / haiku 12 % / fable 1 %; **only 14 agents declare a `tools:` allowlist** (188 grant everything); only 47 have any `## Output` section; 61 agents are byte-similar duplicates of other roles; at least 5 documented model-tier contradictions between `docs/agents.md` and the files themselves.

**The anatomy that works** (best example: `plugins/agent-teams/agents/team-lead.md`, 92 lines, `fable`, 12-tool allowlist):

- frontmatter is the whole declarative surface (`name`/`description`/`model`/`tools`/`color`); the `description` is **the** routing signal and carries up to three trigger phrases (`Use when …`, `Use PROACTIVELY when …`);
- body follows a stable stack: one-line role → Core Mission → numbered invariants (`## File Ownership Rules` 1–4) → ordered lifecycle protocol (7 named operations) → behavioral traits;
- **length anti-correlates with quality** here: the engineered agents are 55–120 lines; the template agents are 150–400 lines of domain prose (`tdd-orchestrator` lists 60+ unranked capability bullets).

**Ten patterns to adopt (P1–P10 — the load-bearing section of the report):**

| # | Pattern | HorizonCode binding |
|---|---|---|
| P1 | **Tool allowlist *is* the role definition** (`team-lead` has no `Write`/`Edit`; `eval-judge` has no `Bash`) | profiles written from the allowlist outward; lint that fails a profile whose prompt mentions an effect absent from its ceiling |
| P2 | **Tier follows blast radius, not seniority** (opus for verdicts, sonnet for transformations, haiku for mechanical extraction, fable only for multi-hour autonomy) | a tier policy for `kind`: verify/plan → strongest; act → mid; research → cheapest unless `requiresReasoning`; resolved tier recorded in `RoutingDecisionV1` |
| P3 | **Named, machine-readable output contract with an escalation ladder** (`SHIP`/`SHIP WITH FIXES`/`DO NOT SHIP`; severity bound to a pipeline action) | `resultSchema` on every profile; `kind=verify` must declare a three-valued verdict + typed findings |
| P4 | **Preconditions declared, not discovered** (“Refuses to plan training without a baseline” in the `description`) | `requiresInputs[]` + `refusesWhen[]` evaluated **before** budget reservation; structured `precondition_unmet` |
| P5 | **Partition fan-out by dimension, not by file** (one reviewer per angle; one debugger per hypothesis) | `FleetSpecV1.partitionBy`; sibling nodes with the same profile must carry distinct partition keys or the graph is refused |
| P6 | **One writer per file, enforced** (ownership rules in prose + “shared files are lead-owned and applied sequentially”) | `ownsPaths` computed at spawn; kernel `files.patch` refuses an effect targeting another session's owned path |
| P7 | **Dev/read/fan-out verbs are separate grants** (five orthogonal verb families; no role gets all) | capability presets `observe ⊂ execute ⊂ mutate` + `coordinate`/`verify`/`publish`; composition only downward |
| P8 | **Read-only is a first-class product object** (five tuned read-only shapes) | invariant: `kind ∈ {research, verify}` ⇒ ceiling excludes write/exec verbs (a reviewer with a shell can `> file`) |
| P9 | **Single-tool relay profile** (exists only to keep bulky results out of the parent context) | `kind=relay`: ceiling is exactly one tool, no commentary, no spawn |
| P10 | **Numbered invariants, named anti-patterns, literal templates** | required prompt skeleton for bundled profiles: Mission / Invariants / Protocol / Inputs / Output contract / Never |

**Ten anti-patterns with the guards that prevent them:** A1 capability-by-superlative (no `## Capabilities` slot; breadth lives in skills); A2 persona inflation without an output contract (schema required); A3 the same role declared many times with divergent settings (canonical id + revision + digest; distinguishable `@provenance`); A4 `inherit` as an escape hatch (opt-in with rationale; class default); A5 empty/contradictory tool declarations nothing validates (`capabilityCeiling=∅` rejected except relay; prompt-vs-grant lint); A6 category as a substitute for capability (never a `category` field in the router); A7 cross-harness lowest-common-denominator prose (**do not copy the compromise** — our ceiling is kernel-enforced; if a surface cannot express a grant, refuse the spawn); A8 file-based handoffs with no artifact identity (adopt-ref digests, never raw paths); A9 orphan-by-omission (teardown enumerated in the profile; assertions at scale); A10 documentation drift (the reference is **generated** from artefacts; CI gates drift).

**Bundling verdict:** 202 agents is the failure, not the feature. The recommendation — **bundle 15 profiles, one per capability class, not per domain** — five load-bearing ones fully specified (`worker@builtin`, `scout@builtin`, `architect@builtin`, `reviewer@builtin`, `lead@builtin`) with exact allowlists, `resultSchema`s, spawn ceilings and isolation defaults; plugins may add profiles only by narrowing, and a “python-expert” is a *skill* over `worker`, not a 20th agent.

### 2.2 OpenHands (Agent Canvas checkout) — the session/wire contract

**Scope caveat (from the report, kept):** this checkout is the React/Electron *client* plus vendored Agent-Server wire types; the runtime/condenser live upstream. Its value is exactly what matters to us: the wire contract and the UI behaviour of sessions, compaction, skills, approvals and delegation.

**Verified facts:**

- **Durable log vs live socket, separated.** `BaseEvent {id, timestamp, source}`; websocket frames: `sync` (declares `from_seq`/`through_seq` **before** replay), `durable {seq, event}` (seq = log index), `transient` (no seq, never persisted), `item_started` (opens a streaming slot **with the id the durable event will carry**), `delta` (masked increments, `order` monotonic per item+attempt), `item_aborted`, `error` (explicitly “distinct from a durable conversation error”). Unknown frame types must be ignored — the envelope is allowed to grow.
- **Client store discipline:** streaming slots live in a *separate* collection from `events` precisely so a provisional id “can never be mistaken for one already seen and dedupe the real message away”; O(1) dedupe by id.
- **Paging with honesty:** `EventSearchOptions {limit ≤ 100, pageId, sortOrder, timestampGte/Lt, excludeFullState, strictPagination}` — `strictPagination` “surfaces unsupported cloud pagination instead of degrading to an empty page… so a partial history is never mistaken for exhaustion”.
- **Approvals are events:** `ConfirmationResponseRequest {accept, reason?}` — the reason flows back as a recordable answer, not an out-of-band command.
- **Condensation is evented view-substitution:** `CondensationEvent {forgotten_event_ids, summary?, summary_offset?}` — condensation “removes events from the LLM's *View*, not from the log”; `CondensationSummaryEvent` keeps the summary separable. Knobs: `max_tokens` (threshold), `condenser_kind ∈ {llm_summarizing, no_op}`, `keep_first` (preserve the opening framing), `minimum_progress` (anti-thrash), and the **hard-reset fallback ladder** (`hard_context_reset_max_retries` × `hard_context_reset_context_scaling`). The UI guards (disabled while busy; baseline captured **before** the request because “the condense POST can return only after the server already emitted its Condensation event”) are a correctness recipe, not polish.
- **Skills:** `SkillScope = project | personal | public` with order `[project, personal, public]`; retired paths (`.openhands/microagents/`) are mapped with a marker and a warning, never silently re-scoped — “legacy source-path mapping is a correctness concern, not polish”.
- **Action↔observation pairing is compile-time structural** (`` `${EventType}Action` `` ↔ one observation type per action) — an unpaired result is unrepresentable.
- **`runtime_services` injection:** the backend's actual bound URLs are forwarded into new conversations as an agent context suffix “so agents use correct URLs instead of guessing ports”.
- **Adapter enforcement as a repo test:** `no-direct-agent-server-calls.test.ts` forbids bypassing the single boundary; per-conversation `session_api_key` carries scoped authority instead of ambient credentials.

**Adopt list (A1–A12, doc-mapped in the report):** evented view-substitution (→10/12); the bounded fallback ladder (→10); baseline-before-request (→10/12); `keep_first`+`minimum_progress` (→10); compaction UX metrics + manual CTA + busy guard (→13/14); skill scopes + legacy markers (→15); typed action↔observation pairing as an invariant (→05/06); durable/transient classes on one stream (→07); sync preamble + strict pagination (→07/12); scoped per-conversation token + mechanical adapter test (→11/14); transport errors ≠ session errors (→06/07); runtime identity in projection cache keys (→12).

### 2.3 SWE-agent — the ACI numbers (the token-economy reference)

**The ACI is container-resident binaries + per-bundle `config.yaml` declarations; the model-facing schema is generated from one source of truth** (function-calling schema for one parser, a `COMMANDS:` text block for another).

**Exact numbers (all read from the tree):** viewer `WINDOW=100`, `OVERLAP=2` (net scroll step 98); `goto(line)` places the target at `line − WINDOW/6` (~17 lines of lead-in); the window header always states `(k more lines above)` / `(k more lines below)`; `search_dir` returns **per-file match counts** and refuses above **100 matched files** (“Please narrow your search”) returning *no* results; `search_file` refuses above 100 distinct lines; the Anthropic-style editor caps **every** response at 16,000 chars with a truncation note that teaches the recovery move (`grep -n` first); `.py` files >16 KB are replaced by a tree-sitter **`filemap`** skeleton eliding function bodies ≥5 lines; the agent layer caps observations at 100,000 chars (10,000 in `bash_only.yaml`) with a hint to use head/tail/grep/redirect; empty output is **narrated** (“Your command ran successfully and did not produce any output.”); an **environment-derived state footer** `(Open file: …) (Current directory: …)` is re-derived by a state command before every turn, never authored by the model; a blocklist stops interactive commands (`vim`, `less`, `tail -f`, bare `python`, …) and the env is tamed (`PAGER=cat`, `MANPAGER=cat`, `GIT_PAGER=cat`, `LESS=-R`, `TQDM_DISABLE=1`, `PIP_PROGRESS_BAR=off`); the editor **lints the postimage and reverts the edit** when a *new* flake8 diagnostic would appear, printing both windows; `review_on_submit_m` forces a staged review loop (re-run repro, remove repro script, `git checkout --` test edits) before submission.

**The “up to 90 % context reduction” claim, evaluated:** the repo contains no such claim or measurement; against the code's arithmetic it is **conditional**: ~90 % for a single 100-line window vs a 1,000-line file dump (true), ~0 % if a model reads a whole file through windows (the overlap re-prints), ~97 % for a broad directory search as per-file counts, ~0 % for a narrow one, 0 % for observation truncation at default settings, and the transcript eliding that does save (%  real) **breaks prompt caching by its own docstring**. Honest framing for us: *“a bounded window with an orientation header and an explicit truncation contract — not a percentage.”* And two devices the report explicitly flags as harmful for us: `last_n_observations`-style transcript elision (cache-breaking) and any window scheme that re-prints overlap at full-file scale.

**Recommended for HorizonCode (report §6):** Phase 1 — extend existing tools (no new authority): read windowing (`cursor: open|next|prev`, `gotoLine`, `view{firstLine,lastLine,totalLines,moreAbove,moreBelow}`, stored per-session cursor refreshed only from *effects*), window-scoped edit with `matchesOutsideWindow` + repair hints, postimage lint gate that reverts, `grep mode:'summary'` with the 100-file abort, append-only `insert`, narrated empty results, truncation `recoveryHint`s, environment-derived state line (never model-authorable, never evidence for `verify`). Phase 2 — an `aci.*` tool group (open/goto/scroll/find/insert) admitted only under a preset so the default tool prefix does not grow.

### 2.4 OpenCode V2 (the `specs/v2` corpus on the dev checkout) — the mature session/tools contract

The most directly comparable design to ours, written as law. Verified facts, grouped by file:

**`session.md`** — inbox-first admission (`session.inbox.enqueued` durable fact → projection row; delivery atomically inserts the visible message; reuse idempotent per session+type, cross-session reuse fails); `steer` is the **default** (delivered at the next Safe Step Boundary; control items like compaction consume without becoming transcript messages); write-ahead **execution claim** committed at busy-period start, released on success/failure/user interruption, **preserved on unclean death** with bounded-attempt recovery that explicitly “does not guarantee exactly-once provider requests or tool effects”; **one Step may have several physical attempts** (≤4 retries, jittered backoff); incomplete stream after durable output → keep partial assistant + synthetic continuation, same budget; **one overflow-triggered compaction** rebuilds the same logical Step, the second overflow is terminal; orphan tool calls from an earlier process are **failed at drain start**, never replayed; **instructions are value deltas** — content-addressed blobs + `instructions.updated {delta, text?}` where “removed” marks absence, an **instruction epoch spans completed compactions**, and a fork adopts the parent's newest instruction values as its baseline; clients display *changed keys*, not privileged prose; `sessions.log({after?, follow?})` subscribes **before** replay and emits one **sync marker at the watermark**; live-only deltas are intentionally absent from replay; “local execution remains process-owned until clustering introduces an explicit placement and fencing protocol” (explicit deferral as good practice).

**`tools.md`** — one structural tool value with **dual output**: `output` (schema-validated machine value, visible to Code Mode), `content` (durable model-facing), `metadata` (compact UI JSON); “a tool without output must provide non-empty model content”; **durable identity** on every call (`sessionID/agent/messageID/callID/progress` supplied by the runner — “the registry does not infer it”); **cancellation discipline** — “effect interruption is the cancellation mechanism… tools must not translate interruption or defects into model-visible failures; broad cause-catching around execute is invalid because it consumes interruption and defects”; **registration overlays** (latest wins; closing reveals the next-latest; a call executes the registration it advertised = “captured execution”); **output bounding** — head+tail with a middle omission marker, oversized payload retained in managed storage replaced by preview, and **“if complete retention fails, execution fails operationally rather than publishing lossy success”**; metadata validated independently (never an unbounded side-channel); storage encapsulation (“domain output does not change according to model-output bounding policy”); and the **cache-preserving final step** — retain tool definitions with `toolChoice: "none"` instead of stripping them “so the cached prompt prefix survives”.

**`event-stream-architecture.md` (Accepted)** — one global subscription → **encode once** → nonblocking offer of the shared immutable frame to **per-connection dropping queues (capacity 4,096)**; the delivery law: “a connection has an independent finite lag budget; exceeding it terminates only that connection while publication and healthy connections continue in order” (overflow ⇒ `SubscriberOverflowError`, drains accepted frames first); the encoding-failure law: fail connected queues with `EncodingError`, skip the malformed event, **keep the feed available for later connections**; benchmark 553.9 ms → 12.4 ms for 50 clients — an encoding-boundary measurement with honest non-claims.

**`provider-policy.md` (Implemented)** — statements `{effect: allow|deny, action, resource}` with wildcards and **last-match-wins**; **safety-inverted precedence**: ordinary settings read forward but **policy documents are read reversed** so user-global beats repository, with organization-managed statements appended last (“an organization deny cannot be lifted by a repository or user allow”); **`tool.use` never grants** — “an allow statement never overrides an agent/session denial or grants a saved approval”, and a deny overrides saved “Allow always”; failure direction: a failed config/credential refresh **keeps the last snapshot** because dropping it would “fail closed for managed providers but **open for policy**”; **enforcement protection** — plugins cannot add/remove/override policy and plugin `remove` operations **ignore** the policy plugin and console provider regardless of selector, “otherwise a repository could switch off enforcement”; denial messages name the decider (“Blocked by <organization>'s policy”); skills denied by policy are absent from the catalog and from every load path (tool, prompt mention, standalone activation); MCP denied servers never open an initial connection; unknown actions are skipped preserving order while malformed *supported* statements remain errors.

**`catalog-config-plugin-lifecycle.md` (Historical; option B selected)** — **replayable transforms**: plugins register a transform over a private draft; disablement closes the plugin scope, the transform unregisters, and the catalog **rematerializes without manual undo** (“lets services rematerialize without manual undo”); one rebuild ⇒ at most one `Catalog.Event.Updated`; deferred plugin activation keeps boot unblocked, and the doc states its own remaining gap (“debouncing those rebuilds needs an additional batching interface”).

**`README.md` (corpus governance)** — an **authority table** (HTTP ops → Protocol; public shapes/durable events → Schema; runtime/persistence → Core; regression guardrails → AGENTS.md), decision records with statuses, historical docs labelled, and “do not add implementation checklists here. Put actionable work in GitHub issues.”

**What V2 had that our docs did not, and we now adopt (V2-1…V2-12):** dual machine/model output; the cancellation taxonomy; registration overlays; fail-closed retention; the cache-preserving final step; instruction epochs + content-addressed blobs; the event-feed laws; the policy statement model (allow-never-grants; enforcement protection; decider-named messages; keep-last-on-failure); replayable transform contributions; corpus governance; `sessions.log` follow+watermark; identity-carrying invocation context (field-name alignment with our `ToolCallV1`).

### 2.5 Code Mode (opencode `@opencode/codemode` + codex-rs `code-mode*`) — decision: ADOPT, DEEPEN, CHANGE three things

**Two real implementations of the same idea, verified end-to-end:**

- **opencode (TypeScript, Effect-native)** — a **purpose-built tree-walking interpreter** over acorn, no V8/WASM: no ambient filesystem/network/process; `Function` constructor is a deliberate rejection; the only call surface is `tools.<path>` plus host-declared extensions; imports resolve only to declared globals; boundary data is JSON with a conversion table (depth cap 32, `Uint8Array` rejected with a hint); limits `timeoutMs` (cooperative, between interpreter steps), `maxToolCalls`, `maxOutputBytes`, intrinsic caps (strings 2²⁴ chars, arrays 10⁷ elements, 10,000 pending promises); **`Result` is always plain data** (`Success{ok,value,warnings,logs,truncated,toolCalls}` / `Failure{ok,error:Diagnostic,…}` with kinds `ParseError`, `UnsupportedSyntax`, `UnknownTool` + did-you-mean, `ToolCallLimitExceeded`, `TimeoutExceeded`, `ToolFailure`, …); `toolCalls` retains **every admitted call in order, even after failure**; hooks `tool.before/after` are the authority seam — a failing `before` **denies** the call and the program sees a normal throw; **static `scanTools`** extracts every `tools.<path>` from the AST and fails on dynamic access/aliasing — the compile-time subset primitive; documented honest gap: a pathological regex can run long (no interrupt hook in the host regex engine).
- **codex-rs (Rust)** — **embedded V8 isolate per cell** on a supervised OS thread (`catch_unwind`; `ThreadPanicked`), JIT disabled (`--jitless`) or Maglev/TurboLEV off; globals expose one JS function per enabled tool plus `ALL_TOOLS` metadata, `store`/`load`, timers; **`console`, `Atomics`, `SharedArrayBuffer`, `WebAssembly` are deleted**; a call serializes JSON → resolver stored under `tool-<n>` → event channel → `cell_actor` → `CellHost::invoke_tool` with a cancellation token → the embedding process executes the **ordinary** tool path → response settles the JS promise. **The isolate holds a name, an index, JSON in/out — never a lease, capability handle, or host object.** Cells are long-lived state machines (`exec/wait/terminate`, `yield_time_ms` default 10 s, `YIELD_GRACE_PERIOD=1 s`); session-scoped `stored_values` are snapshotted per cell (a later cell cannot retroactively change an earlier cell's view); output truncation is owned by client or server mode with separate byte budgets. **Verified gap: `InProcessCodeModeSession::with_options` resets `max_heap_size_bytes` to `None`** — the main cell path does not currently enforce a heap cap (the UI helper isolate does: 0–64 MiB).

**Decision (report §5):**

- **ADOPT unchanged** — the existing `code_mode` shape in doc 09: capability `codemode.execute`, `external-effect` as the declared maximum, `ask` per call showing the subset, kernel lease + one lease per inner call, compile-time `ToolNotInSubset`, and the partial-`toolCalls` audit table on mid-way failure. Both implementations validate every element of it.
- **DEEPEN** — (1) projection/namespacing exactly as opencode: `tools.<path>`, dots as separators, namespace descriptions joining discovery, one canonical spelling (bracket rendering for non-identifier segments); (2) **progressive discovery inside the snippet**: `search()` lowers to the ordinary `tool_search` pipeline (admitted, counted, paginated) — never a private registry read; (3) subset enforcement **static and total** via the scanner (reject dynamic access/aliasing); (4) per-call before/after hooks as the authority seam (deny-on-before-failure; after observes success/failure/**interrupted**); (5) **state persistence as an explicit bounded capability**: `store/load`, JSON-only, session-scoped, snapshot-per-exec, never authority, receipted when it carries mutation-derived values.
- **CHANGE (three corrections to our text):**
  - **C-1 — “QuickJS-class isolate” is not a confinement claim.** Replace with a **guarantee vector** (NF-016 shape: filesystem/network/process/limits/credentials/workspace-fence, each `enforced | best_effort | unsupported` + typed residuals), and name the two acceptable backends: (i) allowlisted-subset interpreter (opencode), (ii) engine with JIT/codegen disabled + ambient globals deleted + heap cap actually set (codex, fixed). “QuickJS-class” must never decide confinement — the vector does; fail closed with `SandboxUnavailable` if the minimum cannot be met.
  - **C-2 — the inner-call audit row must carry host identity:** `{toolId, toolCallId, leaseId, receiptId?, terminalState, ms}` — ms/ok cannot be reconciled against the ledger; read-only calls emit no effect-claiming receipt.
  - **C-3 — persistence and long cells are first-class, not implicit:** `cellId?` + `action: exec|wait|terminate`, default *yield* rather than kill, and the rule that **termination never counts as settlement** — in-flight calls settle or become `UNKNOWN` and enter reconciliation; cell state commits only from a terminal event, and no cell survives session termination.
- **New NF required** — code-mode-specific invariants (subset soundness, nested-call authority, confinement vector, snippet-state scope) belong to no existing entry: create **NF-051** (below), depending on NF-001/NF-016 (+ NF-015 for the native engine path).

**The kernel must still enforce (top risks, verbatim-graded):** lease amplification bounded *before* the cell starts (per-step lease ceiling, per-inner-call budget, `maxToolCalls`, outer wall clock); subset smuggling (no extra names, no `ALL_TOOLS` promotion to callables, no reachable `admitTools`); data→authority laundering (decisions computed from the canonical request, **never** from snippet state); settlement honesty across the isolate boundary (kill ≠ failure: `UNKNOWN` + reconciliation); confirmation bound to the actual subset + snippet hash, single-use; resource exhaustion (the codex heap-reset bug is the test to write); output as injection vector (bounded, marked, never authoring receipt ids/claims); concurrency sequencing of many in-flight receipts; session-scoped persistence cleared/forked correctly.

## 3. Cross-cutting learning themes

**T1 — Contracts over prompts.** Every source that works replaced prose admonition with a structural contract: wshobson's engineered minority (allowlists as job descriptions, three-valued verdicts), OpenHands' typed action↔observation pairing, V2's dual-output tools and cancellation taxonomy, Code Mode's compile-time subset. HorizonCode's existing instinct (kernel-enforced ceilings, result schemas, receipts) is validated; the learning is to push it into the *profile* layer (resultSchema, requiresInputs/refusesWhen, partition keys) and the *tool result* layer (machine vs model output, recovery hints, terminal states), not only the effect layer.

**T2 — The harness carries the reliability, not the model.** SWE-agent's `session-start` on haiku with a fixed template; the `bash_only.yaml` low-cap split-observation config; OpenHands' `keep_first`/`minimum_progress`; codex cells that yield rather than die. A cheap model with a tight contract beats a strong model with prose — which is exactly the lever for the “cheap model ⇒ Claude-class output” goal (NF-056, NF-057).

**T3 — View vs log separation, everywhere.** OpenHands condenses *views* (`forgotten_event_ids`), not history; V2's instruction deltas and compaction rebuild the same logical Step; SWE-agent's window is a view over a file with an orientation header. Our context compiler already separates log and provider view; this pass adds the missing vocabulary (epochs, forgotten sets, view cursors) and the rule that **a view must be reconstructable from the log at any time**.

**T4 — Authority seams must be structural.** The pattern repeats: before-hooks that deny (Code Mode), terminal policy transforms that filter (V2 policy), kernel-boundary checks that receipts attach to (ours), repo tests that forbid bypassing the single adapter (OpenHands), enforcement modules protected from removal (V2). Adoption: the policy-statement model (NF-058), the enforcement-protection rule, and the “do not copy the compromise” ruling (A7).

**T5 — Bound everything.** 100-line windows, 100-file search aborts, 16 KB editor responses, 4,096-frame queues, 4 physical attempts, one overflow-compaction, bounded retention with fail-closed on retention failure. Every bound in the sources has a named recovery move attached to it; our bounds must carry `recoveryHint`/typed residuals the same way.

**T6 — Replayability as a design obligation.** V2's replayable catalog transforms (disable = replay-without-it), wshobson's artifact-digest handoffs vs file-path handoffs, OpenHands' sync preamble and strict pagination, our event log + adopt-refs. The fleet consequence: a run must be replayable from the event log alone (`{node, input digests, output digest}` per step).

**T7 — Cache discipline is a first-class constraint, not an optimisation.** The two cache-breaking devices found in the wild (`last_n_observations` elision — acknowledged by its own docstring; any scheme that mutates the tool-definition block mid-session) are both prohibited for us. Prescribed instead: byte-stable prefix, append-only logs, `toolChoice:"none"` for the final step, breakpoints placed by the provider-policy engine (doc 10), and prompt-cache-aware compaction (summaries append at the tail; the prefix survives).

**T8 — Governance of the spec corpus itself.** V2's authority table + statuses + “no checklists in specs”, wshobson's generated-reference rule (drift caught by CI), OpenHands' mechanical adapter test. Adoption: doc 27 §2's documentation-of-record rule, the recount gate (doc 24 R12), and keeping implementation checklists *out* of the spec set (they live in doc 27 and the task tracker).

**T9 — Don't regress where we are already ahead.** The v2 cross-check found places where HZ's spec is stronger than the source, and those must survive the borrowing: projector **digests + shadow-rebuild verification** (doc 06 E-38…E-46) vs v2's plain projector list; event **versioning + reader gating** (E-31…E-37) vs v2's bare `version: 1`; HZ's **resumable** backpressure policy (doc 07 C11: `page_end`/`resnapshot_required`) vs v2's terminate-the-connection choice — absorb v2's *encode-once + subscriber isolation* rationale, keep our policy; and doc 12 §4.8 already names the claim implementation it intends to inherit. Borrowing runs in both directions.

## 6. Verdicts on the brief's specific questions

1. **Code Mode — integrate?** **Yes, deepen.** The capability, tool and authority shape we designed survives contact with two independent production implementations unchanged; the three corrections (C-1 confinement vector, C-2 receipt-bearing audit rows, C-3 first-class cells) and the CM rules land in NF-051.
2. **Small/cheap models (DeepSeek-class flash) producing frontier-grade output?** **Structural, not aspirational.** The mechanism is the tier-parity program (NF-056): tight contracts + strict-REPL variants + ACI bounded outputs + governance loop, measured by paired evals with a release-blocking ratchet. Speculative decoding (NF-057) addresses cost/speed, not quality; it is adopted as a local-inference feature, not as a quality lever.
3. **ACP as the plug-in standard?** Already specified in the spec set (docs 01/24 ACP rows). This pass adds nothing that changes it; the agent-side surface benefits from NF-060's framing laws. **No change.**
4. **Preview environments ("vibe coding")?** **Adopt (NF-055)** — ephemeral sandboxed previews with bound-URL injection; explicitly scoped to UI-ish work, not the default loop.
5. **ACI, recorders, governance blueprints?** **All three adopted** (NF-052, NF-054, NF-053) with the honest ACI finding: the value is a bounded window with orientation and a truncation contract — *not* a claimed 90 %.
