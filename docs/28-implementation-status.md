## 3. Semantics rulings made during implementation (binding)

1. **Issued leases are honoured by both implementations.** The kernel (`guard.rs`) consults caller-supplied leases (expiry-filtered) ∪ internally held leases; the TS fallback (`LocalKernel.checkGuard`) merges the same way. An expired *copy* passed by a caller cannot revoke a held lease — expiry happens by time. Tests assert this ordering deliberately.
2. **`arguments` is always a JSON string.** No-input tool calls produce `{}`, never `""` (both adapters fixed).
3. **`log.read` `limit` is strict** — `limit:0` returns zero events (kernel fix).
4. **Guard defaults** (no `policy.json`): `fs.read`/`fs.write` inside workspace → `allow`; outside → `ask`; `shell.exec`/`net.fetch`/`spawn` → `ask`. Precedence is not restated here: it is owned by `docs/11-authority-safety.md` R1 (the shipped guard's divergence is §4 gap 5).
5. **Headless approvals fail closed** (auto-deny with a notice). PTY/TUI prompts y/n/a (`a` = session lease).
6. **Zero-config default is the mock provider** — chat must work with no keys. Real providers via `HZ_PROVIDER` + keys or `~/.hzcode/config.json`.
7. **Delegation is an optional capability on the context.** `ToolContext.delegate?: DelegateRunner` — present on parent runs, absent in child runs; a subagent's tools are exactly the seven base tools (children are filtered in both `toolSpecs` and `getTool`).
8. **Skills activate per turn.** `/name rest` injects `## Active skill: name` + body (cap 8000) into the system prompt for that turn only and sends `rest` (falling back to `Apply the <name> skill.` when bare) as the user content; the directory section caps at 12 skills.
9. **The base system prompt is data.** `app/src/core/prompt/` holds the static sections (identity, loop, tools, safety, git, communication, quality; about 700 estimated tokens with the environment block, the test cap) and a request-time environment block (cwd, date, OS, shell, git yes/no, kernel trusted/untrusted, plan mode, the tools actually visible). Wire order: static prefix, environment, project memory, per-model block, rails. Subagents get a child prompt (task, tool subset, no questions, concise report, no inherited approvals) and now inherit the project instruction files. Snapshot goldens in `app/tests/core/fixtures/`.
9a. **Instruction files are peers with one precedence (stage 2).** `app/src/core/instructions.ts` loads, least to most specific (later wins; the user's chat wins over all): user `~/.config/horizon/` AGENTS.md/CLAUDE.md, then per directory from repo root to cwd AGENTS.md, CLAUDE.md, GEMINI.md, CONVENTIONS.md; at the repo root also `.github/copilot-instructions.md`, `.cursorrules`, `.cursor/rules/*.mdc` and `.windsurfrules`; then `.hz/AGENTS.md`, `ZH.md`, and local overrides (`CLAUDE.local.md`, root to cwd). Order is position-major, so a nested AGENTS.md never precedes a root CLAUDE.md. Justification from the reference agents: AGENTS.md (codex, opencode, grok-build, oh-my-pi), CLAUDE.md and CLAUDE.local.md (claude-code, grok-build), GEMINI.md and `.github/copilot-instructions.md` (oh-my-pi), `.cursorrules`/`.cursor/rules` (oh-my-pi, grok-build, cline), `.windsurfrules` (oh-my-pi, cline). CONVENTIONS.md (aider's convention) has no listed reference; it is supported as a plain peer file. `.mdc` rules load only with `alwaysApply: true`; glob-scoped or description-only rules are listed under `/memory` as "not applied", because injecting a path-scoped rule globally would misstate its scope. Dedup: the same real path, or the same text under a different kind, loads once. The 32 KB/file and 128 KB total caps, symlink-escape refusal and "conventions, not authority" framing apply to every kind; each block is attributed (`--- rel (kind)`) under a short follow-instruction. **Lazy nested injection:** `LazyInstructions` registers the not-yet-loaded AGENTS.md/CLAUDE.md in the ancestor chain (inside the repo) of any path a successful read/write/edit/apply_patch/ast_edit touches; each is loaded once (32 KB each, 64 KB per session; the lazy registry is in-memory, so it lasts for the life of the process and a restart or resume drops it until a tool touches the directory again), rendered as an attributed untrusted `<nested_instructions>` block on the system rail ahead of the other rails (append-only, stable prefix untouched), never a user message. **`/memory`** (alias `/instructions`) lists loaded files with kind, size, truncation, skips and unapplied rules. **`/init`** runs an ordinary turn that inspects the repo read-only and writes AGENTS.md through the normal `write` tool with plan mode on (staged; `/changes` to review, `/apply` writes through the normal guard, which asks only where it would ask for any write; the staged diff review is the user's approval of the content); without plan mode the write takes the normal guarded path. Tests: `tests/core/instruction-peers.test.ts`, `tests/core/instruction-hierarchy.test.ts`, `tests/tui/memory-init.test.ts`. Lazy fragments are held per session (a later user turn keeps them), a file skipped because the 64 KB lazy budget is used up raises a notice, and `/memory` lists the lazy fragments and budget skips for the current session. Discovery runs after a SUCCESSFUL path-touching call, so the call that first touches a directory (including a `write` or `apply_patch` Add File into an unread directory) runs without that directory's rules: the rules reach the next request, and a pre-call load cannot help a call the model has already issued. `grep`, `glob` and list do not trigger discovery. Identical text under another kind keeps the first (least specific) copy, which changes attribution only. The main-agent prompt order is static prefix, project memory, per-model block, environment, rails.
9. **Code mode is one bridge, no registry.** Programs see only `tools.call(name, args)`; the parent resolves against the base seven, guards and receipts every executed call; "unknown tool" is an ordinary call result.
10. **Previews are session-scoped process groups.** Spawned detached; stop SIGTERMs then SIGKILLs `-pid`; failures never leave orphans. The registry is in-memory per session.
11. **Kernel refusals are final.** `KernelClient` falls back to the local kernel only on transport failures (exit, timeout, malformed output, unknown request id). An error *response* from the kernel is surfaced to the caller and the mode stays `trusted`; a refusing guard fails closed at the `GuardGate`. Refusing was previously indistinguishable from unreachable.
12. **Chain anchors.** Every `*.jsonl` chain carries a `<file>.head` anchor (seq + hash of the last record), written atomically after each append. `log.verify`/`receipt.verify` compare the chain against it, and appends refuse when tail and anchor disagree. An absent anchor is a legacy chain and is accepted; §4 gap 7 records the residual. **Amendment (2026-11-07, wave 9):** anchors are optionally keyed — with `HZ_ANCHOR_KEY` (hex, ≥32 chars) each `<file>.head` stores `HMAC-SHA256(key, canonical record preimage)` instead of `sha256`, byte-for-byte in both implementations (RFC 2104 over the existing `sha2` crate, pinned by RFC 4231 vectors); a legacy (unkeyed or absent) anchor under a configured key fails closed with `HZ_PRECONDITION_FAILED: legacy (unkeyed) anchor …` unless `HZ_ACCEPT_LEGACY_ANCHORS=1` (verify accepts; the next append re-anchors keyed); a wrong key reports tamper (`brokenAt`), never ok; no key configured = byte-identical legacy behaviour. §4 gap 7 records the closed/residual split.
13. **Scopes and lease patterns.** `scopeFor` resolves symlinks (workspace and target, through the deepest existing ancestor) before classifying inside/outside. Lease patterns are exact or trailing-`*` only — identical in both implementations — and an empty pattern is refused rather than widened to `*`.
14. **Batches run by concurrency class (NF-072).** A batch is split into segments: consecutive `shared` calls run concurrently (`Promise.all`, all-settled — one call's failure cancels no sibling); an `exclusive` call is its own barrier. Every call still resolves, guards, leases and receipts individually, and the whole sequence lands on the same event chain. `GuardGate` serializes `check`/`approve`, and an approval passes the action it answers so concurrent asks cannot cross-wire. `concurrencyClass` is additive on `Tool`; absent means shared.
15. **Loop safety rails (NF-073).** Budgets (`RunBudget`: steps, tokens, wall clock) are checked in one sentinel before every provider dispatch, under one convention — `0` (or absent) is unlimited. A turn is charged before it runs, so a billed-but-failed turn still spends its step, and reported usage is charged even when the turn ends in an error. A run reports one RC-7 terminal outcome (`RunExit`); budget stops are `budget_exhausted`/`timeout` (exit 5 per the canonical table) and the wall clock is never reset or lifted. A batch in which no tool call carried parseable JSON is a format-error step; any clean call resets the streak; 3 consecutive steps fail the run (`format_errors`, exit 1). The corrective text rides the next step's system rail — the Anthropic adapter drops mid-history `system` roles, so it must not be a history message. `BudgetLedger` is one ceiling per run tree: subagents get a child slice that checks the parent first and charges both, serialized on a mutex. `RunBudget`/`RunExit` and the optional `budget` on `RuntimeOptions` are additive contract changes; `runtime.send` returns `exit?`.
16. **Edit-application ladder (NF-069/052 extensions, A-1…A-5).** When exact matching finds nothing and the reflection slot is unspent, `edit` escalates: relative-indent normalisation (strip each block's common prefix, compare, and re-indent the replacement by the window's prefix preserving relative depth) → 3-way (trim) merge (every line equal after `trim()`) → line-patch (first/last non-blank lines as anchors, same span length). A rung applies only when exactly one candidate exists; several candidates fail with the named rung and candidate line spans and no write. Failures return diff-shaped feedback — the closest actual window as `-`/`+` pairs with a similarity percentage, plus a REPLACE-already-present note with line numbers. The reflection slot (`MAX_EDIT_REFLECTIONS = 1`, keyed per session and file, cleared by a successful edit) allows one repair with that feedback; a second failure disables fuzzy matching for the file (exact matching still works). Error and success strings are a contract (A-5), pinned byte-identical in `tests/tools/edit-ladder.test.ts`; fuzzy successes append `(matched via <rung>)`, exact successes do not.
17. **CI gate runner and ops tree (pass-5 C.3).** `ops/gates.sh` runs the six gates that exist in this repository today (Rust suite, kernel selftest, TS suite, headless smoke asserting tool-exchange output and a non-empty receipts chain, budget-rail exit 5, usage-error exit 2) — fail-fast, temp-logged, hermetic (mock provider, throwaway HOME, no network). `ops/gate-catalogue.md` maps every one of the 18 `docs/24` §3.5 gates, all `declared-gap` with the missing surface named per row; a row flips to `runnable` only in the change that makes it run. The GitHub Actions workflow cannot be committed by the automation identity (its token has no `workflow` scope — the first push attempt was rejected on exactly that, and the unpublished commits were rewritten locally to drop the path; nothing was published, no force-push involved): it ships as the tracked payload `ops/ci/github-actions.yml`, installed by `ops/install-ci.sh`. It claims no §3.5 gate is enforced.
18. **Context-cost contracts (NF-074).** Every provider request's output cap is fitted from the last reported usage (`inputTokens + outputTokens` as the anchor base, plus locally estimated appended deltas): `min(8192 ceiling, window − anchor − 4096 headway)`, floored at 256; before any anchor exists the whole prompt is estimated locally (bytes/4 + 16-token framing per message, tool-call arguments and the tool-schema blob counted). Tool results are capped at 16 KiB / 4,000 tokens: truncation is line-aware and lossless-resumable — the kept region is a true prefix and `nextOffset` is its byte length — and the full text spills to `<ws>/.hzcode/spills/<sha256>.txt` with a marker pointer; a caller-supplied stream cap that is exceeded fails the call without spilling (never spill a clipped stream); receipts always digest the full output. The shell minimiser (ANSI/OSC, CR progress, trailing whitespace, blank runs) runs by default with a visible `[output minimised: …]` flag, byte-identical when nothing changed. `cat <file>` (exactly one plain argument, `VAR=` prefixes skipped) intercepts to the read tool with a `guard` `fs.read` admission and a visible notice; terminal programs and forever-stream tails (`tail -f`) are refused before Guard, with `HZ_ALLOW_INTERACTIVE=1` the documented override. Local estimates are for fitting only — never for accounting.
19. **Repo-map ranking (B-1, doc-09 §4.2 `repo_map`).** The map is a def/ref graph scored by personalised PageRank: definitions come from per-language lexical patterns (exported/`pub` declarations first, then locals — no tree-sitter dependency, the reduced form the doc's "no embeddings, no index service" clause allows), references are whole-identifier occurrence counts, and edge weight is sqrt(refs) × (1 + 50 for idents defined in focus files) × (10 for focus-file out-edges) — the aider weight table as the starting prior. Rendering binary-searches the ranked file list for the largest prefix within the token budget (default 4,000, hard 16,000) and appends `[repo_map: n files, ~t tokens]`, plus an explicit `[truncated: …]` marker when files are omitted. Files with no definitions never enter the body; test-shaped paths are excluded unless `includeTests`; output is byte-stable for a fixed tree+params (cacheable and comparable); one `fs.read` admission per call. Not built here: the persistent `hz_index` side (docs/10 R97/R103) — this tool is index-free by design.
20. **Canonical JSON numbers (docs/05 D40; closes pass-5 C.1).** The canonical number form is fixed as the IEEE-754 doubles serialized by the ECMAScript shortest-round-trip algorithm that `JSON.stringify` implements (`0.1` → `0.1`, `1e21` → `1e+21`), with negative zero normalised to `0`, `NaN`/`±Infinity` refused (never silently `null`), and integers at or beyond ±2^53 refused in decimal form. Enforced TypeScript-side by `validateCanonicalNumbers` in `app/src/core/canon.ts` — a walk invoked by `canonicalJson` that throws `CanonicalNumberError` naming the value's JSONPath-style location (`$.payload.limits.count`) before any serialization; all valid inputs stay byte-identical, so `hashEnvelope`/`hashReceipt`/`digestOf` are unchanged. Tests: `app/tests/core/canon-numbers.test.ts` (10). Residual, recorded: `contracts.ts`'s header and `kernel/src/canon.rs` still describe floats as outside the v0.1 interop contract, and the Rust serializer is not yet aligned — the next kernel wave carries that.
21. **Internal capability IDs (closes pass-5 C.2).** The doc-11 §4.1 runtime-internal IDs now sit in a labelled INTERNAL (non-canonical) block in `_conventions.md` §5: they MUST NOT cross any surface, MUST NOT satisfy a registry-parity check for a canonical ID, are promoted into the canonical list in the change that first implements their feature (RC-11), and are a defect if they outlive two revisions without promotion or withdrawal. `docs/24` §3.3's proposals keep their Reserved status and point at the block; nothing was promoted.
22. **Managed runtime v1 (NF-071).** Every owned child spawns through one `spawnOwned` (`core/owned-spawn.ts`): the ledger row (`<stateDir>/spawns.jsonl`) is appended before return, and a ledger that fails to parse is renamed `spawns.jsonl.corrupt-<epochMillis>` and read as `corrupt: true` — a refusal state, never an empty history (the spawn lint allows exactly one `Bun.spawn` site, and every allowlist entry must carry a reason). Identity is `{pid, startTicks}` from /proc field 22 (`core/worker-identity.ts`): a dead pid or reused pid is refused; ancestor-chain proving is deferred and stated in the module. A long-lived child must be detached and gets the poll-based `sh` owner-death supervisor (`core/supervisor.ts`, ~100 ms, `kill -9 -<worker-pgid>` on any owner death incl. SIGKILL/OOM). The admission FIFO (`core/admission.ts`; table created migration-safely in `session.ts`) admits once by id; an `unknown` row halts followers — `nextRunnable` refuses and only `resolve(requeue, drop or cancel)` unblocks — and `recoverInterrupted` settles `running`→`unknown` with evidence `interrupted`. Crash-recovery wiring (2026-11-09 server-rewind wave, external audit finding 2 closed): `createRuntime` now calls BOTH recoveries on session open/resume, before the first turn — `repairDanglingToolCalls` (TRANSCRIPT: the dsh ToolCallRecovery pairing invariant, wired since wave 10) and `recoverInterrupted` (ADMISSION FIFO: previously dead code on the live path, now invoked so a `running` row left by a killed turn becomes `unknown`/`interrupted` and halts followers instead of silently replaying). The two are complementary, not duplicative — one keeps the provider-replayable history valid, the other keeps the work-queue honest — and both are idempotent, so a repeated open is a no-op. Tests: `tests/core/crash-recovery.test.ts` (4, incl. a revert check that fails if the `recoverInterrupted` wiring is removed). Not in this slice: the framed owner/worker control pipe; the FIFO is consulted at open, not yet driving `loop.ts` dispatch turn-by-turn.

64. **Hashline anchors (runtime-depth FEAT-003).** New pure module `app/src/tools/hashline.ts`, after grok-build `grok_build_hashline/scheme.rs` (`research/compare-codex-grok.md` section 2.2). An anchor is `LINE:LOCAL:CONTEXT`: LOCAL is three letters hashing the line with all whitespace removed (an indent change does not stale it), CONTEXT is three letters hashing the previous and next lines' LOCAL hashes (a repeated `}` is not a free pass). This is a deliberate variant of grok's ChunkFingerprint: a chunk fingerprint changes whenever an insertion moves a chunk boundary, which would defeat shift recovery. `read` gains `anchors?: boolean` (default false; the default rendering is the same code path and byte-identical, so the prompt cache is unchanged apart from the one-time schema text). `edit` gains `start_anchor` and optional `end_anchor` in place of `old` (mutually exclusive with `old` and `all`; `required` is now `path`, `new`, and the string mode still reports `old is required`). Each anchor resolves Valid, Stale or OutOfRange; a Stale or OutOfRange anchor recovers only when exactly one line within +-15 lines validates (LOCAL and CONTEXT), a second candidate is a refusal naming every candidate line, a truncated anchor (no CONTEXT) is Stale and a malformed one does not parse. The whole line range becomes `new` (an empty `new` deletes it); the replacement takes the range's native line ending, so CRLF files stay CRLF. Same discipline as string mode: guard, then approve (when `ask`), then the per-file lock (ruling 63), the preimage sha256 re-check, atomic write, read-back verify and a change-journal record; anchors are resolved against the exact bytes whose sha256 is re-checked. Anchored mode needs no prior-read ledger entry because the anchors are themselves the proof of freshness. Plan mode refuses to stage an anchored edit (only the exact string rung is projectable). Named residuals: LOCAL and CONTEXT are 15 bits each, so a collision can make a stale anchor look valid or a shift look ambiguous (the second is a safe refusal; the first needs a changed line whose neighbours hash identically); anchors are line-only and do not cover mid-line edits. Tests: `tests/tools/hashline.test.ts`.
65. **Speculative execution: decision to leave UNWIRED, flag pinned inert (runtime-depth FEAT-004; supersedes the "consumer must define" note of ruling 47).** `LoopDeps.speculativeExecution` stays off by default and still changes nothing. A kept speculative result cannot soundly REPLACE the real call today, for four reasons found in `loop.ts`. (1) *No commit window.* `streamTurn` collects `turn.toolCalls` and the batch runs only after the provider stream is done, so the model has already committed every call; the only pre-commit window is mid-stream, where events cannot be rolled back. (2) *Ordering.* `batchSegments` keeps reads after an earlier write in a later segment; a read run ahead of that write would return pre-write content, and sound dependency inference across segments is exactly what ruling 47 left out of scope. (3) *Hook bypass.* The speculative host deliberately skips user `tool.pre`/`tool.post` hooks and declines `ask` without prompting; a kept result substituted for the real call would skip a user's pre hook (which may deny) and the approval prompt, a policy bypass, while re-running them defeats the point. (4) *Exactly-once.* `runToolCall` owns `tool.card`, the `tool.call` and `tool.result` log events, the receipt, the lazy-instruction discovery, the transcript row and the mistake/loop rails; splitting it so a precomputed result slots in changes the shared path for every tool. Reads in the same batch already overlap through NF-072, so the remaining gain is small against that risk. Test: `app/tests/core/speculation-unwired.test.ts` runs the same two-read script with the flag absent and on and requires identical guard checks (each `fs.read` exactly once) and `tool.card` counts; a naive wiring that runs the read speculatively and again for real fails it. Wiring is revisited only with a design that keeps `tool.pre` hooks and approval in front of any kept result. Status: DECISION RECORDED, TESTED.
