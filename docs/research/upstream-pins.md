# Upstream pins and URL mapping

This is the reusable mapping from the local read-only clone names used in HorizonCode research to their GitHub repositories, the exact commits that were read, and the URL pattern for linking to a file. Any future doc that steals from or adapts an upstream repo should link through this table so the next reader can open the exact lines that were studied.

## URL patterns

- File at the pin: `https://github.com/<org>/<repo>/blob/<full-sha>/<path>`
- File with a line range: `https://github.com/<org>/<repo>/blob/<full-sha>/<path>#L<start>-L<end>`
- Directory at the pin: `https://github.com/<org>/<repo>/tree/<full-sha>/<path>`
- Always use the full 40 character SHA. Branch names (`main`) drift; the SHA does not.
- Verify the path exists before writing a link: `git -C <clone> ls-files | grep -Fx '<path>'`. Never invent an upstream path. If a path cannot be verified, write the text `path not verified` next to it.

Notes on specific pins:

- **grok-build:** the research notes quote `SOURCE_REV 559751f...` from the upstream tree (a sync marker from the SpaceXAI monorepo). That is not a git commit of the public repo. The clone that was read is at `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`, and that is the SHA used for every link.
- **claude-code:** the public repo holds docs, examples and `mods/` only, not the agent source. Claims about Claude Code internals come from those docs and the published SDK documentation, not from source.
- **opencode:** GitHub may redirect `sst/opencode` to a renamed organisation. The `sst/opencode` blob URLs with the full SHA were written as read; if a redirect breaks them, resolve the new owner from the repository page and keep the same SHA.
- **Short SHAs in prose:** several notes cite 7 character short SHAs (for example `a22b492`). They are prefixes of the full SHAs above.
- **HorizonCode itself:** research notes refer to HorizonCode commits `79f525c` (main at the time of forgecode-deep) and `d1838f8` (branch `feat/tui-polish`, grok-tui-deep). Those are this repository's history, not upstream.

## Rules for future docs that take from an upstream repo

1. State the intent per item: **direct** (code or text copied verbatim, so license and attribution must be checked first) or **adapt** (idea reimplemented in HorizonCode's zero-runtime-dependency style).
2. Link the exact file at the pinned SHA, with `#Lx-Ly` when the lines matter.
3. Record deferrals next to the item with the word `DEFERRED` and the reason.
4. Add the repo to the pins table here if it is new, with the full SHA.
5. Do not paste secrets, tokens or local absolute paths (`/projects/...`, `/data/home/...`).
